```bash
npm run dev          # node ace serve --hmr  (HMR boundaries: controllers + middleware)
npm run build        # node ace build -> ./build (production bundle, runs vite build hook)

node ace migration:run       # ALSO regenerates database/schema.ts (see below)

```

```bash

node ace test unit                    # one suite
node ace test --files="money"         # one file / filter by filename fragment
node ace test --tests="formats minor" # a single test by title
```

## Stack & surfaces

AdonisJS 7 + Lucid (Knex) + Edge + Vite/Alpine, ESM-only, Node ≥ 24, `#`-prefixed subpath imports (see `imports` in [package.json](package.json)).

The app serves **two surfaces** with different auth guards ([config/auth.ts](config/auth.ts)):

- **Web** — server-rendered Edge pages (`/`, `/signup`, `/login`), `web` session guard, controllers resolved through the generated `controllers` registry.
- **JSON API `/api/v1`** — consumed by a Flutter mobile client, `api` guard with opaque bearer tokens (`hst_…`, hash-only storage, **no expiry** by design — logout revokes). Routes lazily import their controllers directly.

Both are wired in [start/routes.ts](start/routes.ts).

## Generated files — never edit by hand

- [database/schema.ts](database/schema.ts) — regenerated by `node ace migration:run`. It holds one `XSchema` base model per table with all `@column` declarations. **Models in [app/models/](app/models/) extend these classes** (`export default class Transaction extends TransactionSchema`) and add only relations, serialization overrides, and getters. Adding a column = write a migration, run it, then use the regenerated column.
- [.adonisjs/server/controllers.ts](.adonisjs/server/controllers.ts) — the web-controller registry, produced by the `indexEntities()` assembler hook.

## Money and the sign system (the core of this codebase)

Amounts are **positive integers in minor units** (`amount_minor`); never floats. [app/services/money.ts](app/services/money.ts) converts using each currency's ISO-4217 exponent (0/2/3 decimals) and produces the `{ minor, currency, display }` shape the API returns for every money field.

A transaction row carries **no sign**. Direction is derived entirely from `type`, through three independent conventions that all live in [app/services/balance_service.ts](app/services/balance_service.ts):

| convention | meaning | TS function | SQL twin |
|---|---|---|---|
| debt | +1 = the contact owes the user | `signOf` | `SIGNED_MINOR` |
| cash | +1 = money entered the user's wallet | *(SQL only)* | `CASH_SIGNED_MINOR` |
| held | +1 = user's own money kept by the contact (أمانة) | `holdSignOf` | `HOLD_SIGNED_MINOR` |

The debt and cash signs deliberately disagree (`lend` is +1 debt but −1 cash); `due_to_me`/`due_from_me` exist precisely to record a debt with **zero** cash movement.

**Adding or renaming a transaction type touches all of these** — the TS/SQL twins are duplicated on purpose and silently drift otherwise:

1. `typeValues` in [app/validators/api/transaction.ts](app/validators/api/transaction.ts)
2. `TransactionType`, `signOf`, `holdSignOf`, and the three SQL `CASE` constants in `balance_service.ts`
3. `CurrencySummary['totals']` + the `totalKey` map in `reduceSummary`
4. `shape()` in [app/controllers/api/v1/summary_controller.ts](app/controllers/api/v1/summary_controller.ts) (only types on the wire appear in the chart)
5. `DEBT_TYPES` / `HOLD_TYPES` / `CONTACT_REQUIRED_TYPES` in [app/controllers/api/v1/transactions_controller.ts](app/controllers/api/v1/transactions_controller.ts)
6. A migration widening the MySQL `ENUM` (see [1758943359300_add_due_transaction_types.ts](database/migrations/1758943359300_add_due_transaction_types.ts))

All balances are **computed on read** by aggregating transactions — nothing is denormalized, so there is no cached balance to invalidate.

## Domain model

`user → contacts → ledgers → transactions`, everything scoped by `user_id` (multi-tenant isolation: queries always start from `auth.getUserOrFail()` and a foreign id yields 404).

- A **ledger** is a per-contact "book" in one currency. A contact may have **one active ledger per (contact, currency)** — enforced by a DB unique index — plus any number of archived ones. Controllers auto-create the matching ledger when a transaction arrives in a new currency.
- `transactions.ledger_id` is **nullable**: a null ledger means a personal (contact-less) entry, surfaced as `isPersonal` in the feed.
- Invariants enforced in [transactions_controller.ts](app/controllers/api/v1/transactions_controller.ts) / [ledgers_controller.ts](app/controllers/api/v1/ledgers_controller.ts), each returning a 422/409 with a stable error key: `repayment_exceeds_debt`, `insufficient_held`, `contact_required`, `held_outstanding` (archiving is blocked while held ≠ 0), `active_ledger_exists`. On **update**, the guards recompute the balance *excluding the row's own pre-edit contribution*.
- `defaultCurrency` is restricted to the allow-list in [app/services/currencies.ts](app/services/currencies.ts), kept in sync with the client's `core/constants/currencies.dart`.

## API conventions

Every `/api/v1` response is an envelope: `{ success: true, data: {…} }` or `{ success: false, message | error }`. `message`/`error` values are **stable snake_case keys meant to be translated client-side**, not prose.

[app/middleware/force_json_middleware.ts](app/middleware/force_json_middleware.ts) forces `Accept: application/json` on the whole group, and [app/exceptions/handler.ts](app/exceptions/handler.ts) branches on `url().startsWith('/api')` to map framework exceptions (`E_VALIDATION_ERROR` → 422 `validation_failed`, `E_INVALID_CREDENTIALS` → 401 `invalid_credentials`, …) into that envelope; web routes keep default HTML behavior.

## Database

`DB_CONNECTION` selects `sqlite` (default in [config/database.ts](config/database.ts)) or `mysql`; local development currently runs **MySQL** via `.env`.

Migrations that need dialect-specific DDL use `this.defer(async (db) => …)` and branch on `db.dialect.name` — see [1758943359000_ledger_active_unique_per_currency.ts](database/migrations/1758943359000_ledger_active_unique_per_currency.ts): MySQL gets a STORED generated column (`active_contact_currency`) plus a unique index, while SQLite/Postgres get a partial unique index. `type` enum changes are raw MySQL-only `ALTER TABLE … MODIFY type ENUM(…)`.

## Deployment

`npm run build` emits `./build`; its **contents** are uploaded to an IIS/MonsterASP.NET `wwwroot`. [web.config](web.config) (copied via `metaFiles`) launches `bin/server.js` through httpPlatformHandler and maps `%HTTP_PLATFORM_PORT%` → `PORT` — omitting that mapping causes HTTP 502.5.
